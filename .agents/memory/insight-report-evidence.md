---
name: Insight report evidence builder
description: Pitfalls when building/inspecting the insight-report evidence package (fullContext) and replicating prod runs in dev
---

- **Geo-null skip (fixed July 2026)**: the evidence builder now emits explicit `[EXTRACTION FAILED — …]` prose markers when geocode/zoning/FAR/transit/demographics/childcare/RentCast data can't be read, and the master prompt's FIELD STATUS RULE forbids factual claims on marked blocks. Before the fix, absence was silent and reports asserted things like "Zoning Not specified".
  - **How to apply (replication):** when replicating a prod run into dev for testing, copy FOUR tables: `runs`, `pin_lookup_cache`, `lien_cache`, AND `geocode_cache` (match `geocode_cache.address` lowercase; match `pin_lookup_cache` via `upper(regexp_replace(address,'[^A-Za-z0-9]','','g'))`), and `setval` cache-table sequences before inserting with explicit IDs.
- **Dormant marker contract**: FIELD STATUS RULE also defines `[not present in source records]` (affirmative absence), but nothing emits that string yet — the recorder block says "none found in recorder data" instead. When pipeline work resumes, either emit the exact marker there or reword the rule bullet.
- **Geocode staleness ≠ absence (fixed July 2026)**: `getGeocode` has a 7-day freshness gate meant for the interactive route (which re-fetches on a miss). The report evidence path has no re-fetch, so the gate silently turned valid stale rows into "extraction failed" for zoning/transit/demographics. Report paths must use the any-age lookup (`getGeocodeAnyAge`); do NOT "unify" it with the freshness-gated one.
  - **Why:** zoning, coordinates, community area, and ZIP effectively never change; stale data is strictly better than a false extraction-failure marker.
- **RentCast block only appears if `rentcast_cache` has a row** with `cache_key = <zip>` and `cache_type='market'` — it is never fetched on demand during report generation; absence now emits an EXTRACTION FAILED marker.
- **DIAG char/keyword logging measures fullContext only**, not the assembled prompt. The full payload = master prompt in `server/prompts/reportLogic.ts` (~38k chars, dominates input tokens) + stored property_context + funnel signals + fullContext. Keyword checks are substring-based ("current" matches "rent" — false positives).
- **Canonical project-type strings**: funnel stores canonical business-use names from `shared/businessUses.ts` (e.g. "School (Private K-12)"), but older frontend gates use legacy "School (Private)". Any server-side gating on project type should include both spellings.
- Dev-only evidence inspection: `GET /api/runs/:id/insight-report/evidence` (mounted only when NODE_ENV=development) returns the exact fullContext text without a model call, plus an `X-Evidence-Coverage-Missing` header listing absent checklist sections.
- **Funnel lines are NOT in the /evidence output**: `funnel.*` lines (project type, valuation block, etc.) are assembled inside `generateInsightReportContent` and injected as `ui_context.funnel_signals`, separate from fullContext. Do not conclude a funnel block is broken because the /evidence endpoint doesn't show it — that endpoint only covers the evidence builder.
- **Generation latency**: real report generation with the current model takes ~2–3 minutes (streaming, ~18k output tokens), not the 15–30s the UI copy claims. When testing via curl, use a long timeout or poll `runs.insight_report_generated_at`; the server finishes and saves even if the client disconnects.
- **Stale-report stamp**: saved report content JSONB carries `generatedForProjectType` (JSON null = generated with no project type; key absent = legacy report). The client treats key-absent as "unknown, no banner" — preserve that distinction if reshaping the content object.

## Generation validation (Aug 2026)
- The one-page layout validator must not 500 the user: metadata cell values (landmark names etc.) are real-world data — truncate with ellipsis, never fail. Body/finding overruns are AI verbosity — retried once with the validation error appended to the prompt; only fail after the retry.
- The insight report page auto-generates on first visit (no Generate click); the button remains as Regenerate. Toolbar is light-themed to match the app.

## In-section report, as-is mode & progress (Aug 2026)
- The insight report now lives in a RunDetail slot (button → checklist modal → collapsible section). Toolbar button scrolls + triggers the same control; standalone page still exists.
- **As-is (public record) mode must sanitize at the evidence-builder level**: `buildPropertyChatContext(run, geo)` folds funnel answers, project context, and saved valuation into the evidence text. Gating only the prompt's funnel lines leaks user deal inputs. `buildInsightReportEvidence(runId, {publicRecordOnly})` nulls lastProjectType/Role/TransactionType/FreeformDescription/reportContext on a run clone; stored-context ui_context/onepager_context are dropped too. As-is reports save `mode:"as_is"`, `generatedForProjectType:null`, and must never trip the stale-project-type banner.
- **Real progress**: findings counted by streamed `"status":"red|yellow|green"` matches (never a timer); in-memory progress map keyed by run id; each validation-retry attempt resets count to 0; concurrent generate for same run → 409 (10-min stale window); only the owning attempt object may mutate the map entry.
