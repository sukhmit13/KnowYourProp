# KYP — Step 0: ship the stylesheet. **CSS only. No markup changes.**

🔴 **Supersedes the first version of this document.** That version told you to add
`className="kypwrap"` to every section and also claimed nothing would change appearance. Those two
instructions contradict each other, and the markup half was written against code I cannot see.
**Both are removed.** This step now adds CSS and nothing else.

---

## 1. Why this step exists

Every spec so far — 13, 13b, 14, 15, 16 — has described components by name (`.kyp-block`,
`.kyp-zrec`, `.kyp-says`, `.kyp-xfer`, `.kyp-subhead`, `.kyp-procard`) and has never once shipped
their CSS. Those definitions only ever existed in a mock stylesheet outside this repo.
`client/src/index.css` contains **zero** `kyp-` rules today.

That is why Zoning History shipped with the right content and the wrong appearance. The structure
was buildable from prose, so it got built. The visual language was not in the document at all, so
Tailwind and shadcn primitives filled the gap.

## 2. What this step does and does not do

**Does:** appends ~940 lines of CSS to `client/src/index.css`.

**Does not:** touch a single `.tsx` file. No wrapper class, no markup, no copy, no logic.

Every rule in the sheet is scoped under `.kypwrap`, and **nothing in the app has that class yet**.
So this step is inert by construction: the page must look pixel-identical afterwards. If anything
moves, a rule escaped its scope and that is the bug to fix before going further.

The wrapper gets applied later, **inside each section's own re-ship step**, so the visual change
arrives together with the markup that is meant to use it. That is also where the wrapper's placement
gets decided per section — see §4.

## 3. Why it is scoped, and must never be hoisted to `:root`

Two token names collide with the app's shadcn variables:

| Token | This sheet | `index.css :root` | If hoisted |
|---|---|---|---|
| `--card` | `#fff` | `0 0% 100%` (HSL triplet) | `bg-card` resolves `hsl(#fff)` → invalid → transparent |
| `--muted` | `#8b8a84` | `45 24% 96%` (HSL triplet) | `bg-muted` / `text-muted-foreground` break app-wide |

`text-muted-foreground` is used throughout `RunDetail.tsx`. Hoisting would silently break large parts
of the page in a way that is painful to trace.

**The codebase already contains the correct pattern.** `index.css:4` defines the Incentives
section's tokens on `.incwrap`, not `:root`, and `RunDetail.tsx:7291` applies that class to wrap the
section. Incentives renders correctly for exactly this reason.

Three things from the mock sheet were **deliberately dropped** in this port:

- `*{box-sizing:border-box;margin:0;padding:0}` — Tailwind preflight already does both.
- The font `@import` — `index.html:29` and `index.css:1` already load Instrument Serif, Inter and
  JetBrains Mono. **Do not add another.**
- `body{background:var(--paper)}` — the wrapper paints **no background**. It carries tokens, text
  colour and the body font, and nothing else. A wrapper that repainted its own ground could not be
  placed on an accordion row without changing the page.

## 4. Read this before the next step — where the wrapper goes

The mock's section header carries `06`, `ZONING HISTORY`, the takeaway with **2017 set in Instrument
Serif**, and the `5 ACTIONS · RT-4` badge. All of that is `kyp-` typography, and it sits in the
**collapsed header row**, not the expanded body.

So the wrapper cannot go on the section body alone — it has to enclose the header row too, or the
header can never match the mock. Exactly where it attaches depends on the current accordion markup,
which is not in the copy of the repo I have: `.accrow` and `.acchd` do not appear in it at all.

**Before the next step, paste me the JSX for one accordion section shell** — the row that renders
`06 · ZONING HISTORY · <takeaway> · <badge>` plus its expanded container — and the `.accrow` /
`.acchd` rules from `index.css`. With that I can specify the wrapper's exact attachment point rather
than guessing at it, which is what produced the contradiction in the first version of this document.

**One hazard to check when it lands:** `.accrow.i .num` is a descendant selector. Once a section is
wrapped, it can reach into the body and paint an indigo chip behind any `.num` inside. If that rule
exists in its current form, it will need scoping to a child selector — but confirm the real selector
before changing it.
