# Replit Prompt — Corridor Intelligence — build to spec

Redesign the **Corridor Intelligence** section: a Standard Takeaway on top, four KPI tiles, then one card per nearby commercial corridor (**ordered closest-first**), each showing new business licenses, new construction, and — where present — recent corridor coverage and zoning activity. The takeaway uses the shared **Standard Takeaway component** (Part B). Implement CSS/HTML **verbatim**; check CRITICAL DETAILS.

## 🔴 Governing rules
1. **Report-data-first** (shared rule): `cross_reference_allowed: false` — this section is self-contained. Its takeaway uses ONLY this section's own corridor data. It may fire on its own data-ready with no cross-section wait.
2. **Order corridors closest-first** — sort by distance ascending (`On corridor` / 0 mi first). See LOGIC.
3. **No sentiment coloring on activity** — new licenses, permits, and construction are directional momentum → neutral. The ONE green bullet is the *location* takeaway (corridor frontage is a genuine property-specific strength). Zoning "Approved" is a neutral status tag, not green. No red anywhere.
4. **Honesty on messy source data** — distances are per-item (the "within 0.5 mi" is to each corridor's nearest point; items can sit farther); raw permit "city class" labels are demoted to a muted tag, never the headline. See LOGIC.
5. **Coverage here is corridor-level** — label it as such and point site-specific coverage to the News section (the two never double-count an article).

## LOGIC
1. **Sort corridors closest-first (ascending distance).** Key = `on_corridor ? 0 : distance_mi`, ascending. So `On corridor` renders first, then 0.01, 0.29, 0.47, … Tie-break by name. The tier (1/2) does NOT change order — it's a label, not a sort key.
2. **Expanded vs collapsed** by whether a corridor has any detail data (licenses/construction/coverage/zoning). Chips reflect non-zero counts only.
3. **Distances are per-item.** Show each item's own `distance_mi`; keep the section's "~0.5 mi" as a nearest-point filter in the footer. Don't imply every item is within 0.5 mi.
4. **Raw permit labels demoted.** Lead construction rows with the clean `use · stories · units · cost` line; render `city_class` only as a muted `City class:` tag. Never headline a contradictory raw label.
5. **Coverage = corridor-level**, labeled and cross-pointed to the News section; never re-count a site-specific article here.
6. **No favorability color except the location `.good` bullet.** Activity is neutral; zoning status is a neutral tag.

## CRITICAL DETAILS
1. **Takeaway = shared Standard component**; 4 bullets, exactly one `.good` (location), the rest insight + one caution.
2. **Corridors sorted closest-first** (`on_corridor` = 0). Tier is a label, not a sort.
3. **Per-item distances**, nearest-point filter noted; raw permit `city class` demoted to a muted tag.
4. **Corridor-level coverage** labeled + pointed to News; no double-counting.
5. **Single footer line** (the live version prints it twice — collapse to one).
6. **No sentiment color** beyond the location bullet; zoning "Approved" is neutral. No red.
7. **Serif (`--disp`) ONLY** on the takeaway headline and `.kpi .n`. Everything else Inter/Mono.
8. **`cross_reference_allowed: false`** — self-contained; fires on its own data.
