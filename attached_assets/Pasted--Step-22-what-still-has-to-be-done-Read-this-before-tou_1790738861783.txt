## ⛔ First — one thing not to do

There has been an offer to *"update Corridor Intelligence to the same single-header, continuously
visible report layout."*

**Do not restyle §corridor.** It is being **deleted**, and its content redistributed. Restyling it
would mean carefully applying the design language to 830 lines that Step 4 removes, and would
entrench the problem this whole change exists to fix.

The problem is not that §corridor looks old. It is that **§news splits by publisher and §corridor
splits by geography**, so the same article is filed twice under two different logics. The
cross-section filter that was added — stopping corridor articles repeating what News already showed
— is a patch over that fault. Split by *subject* and the need for it disappears: a story is culture
or it is development, and it lands in exactly one place.

## The corridor boundary is safe. Confirmed.

Before deleting 830 lines, here is why nothing about the corridor rule is lost.

**Everything that defines the boundary is server-side, in `server/newsMonitor.ts`:**

| Thing | Value |
|---|---|
| `CORRIDOR_PROXIMITY_MILES` | `0.5` (line 771) |
| `CORRIDOR_KEYWORDS` | **34 corridors** defined |
| corridors carrying the `line` refinement | **3 of 34** |
| `findNearbyCorridors()` | server |
| `addressMatchesCorridor()` | server |

Deleting JSX cannot touch any of it. `/api/corridor-news` keeps returning `corridors`,
`corridorKeys`, `is_near_corridor`, `mentionsNeighborhood` and `tier` unchanged.

**The 830 lines are rendering, not logic.** The only functional reference inside them is
`isOnCorridor(...)` at `17743` and `18043`, and it is **defined at line 2964** — far outside the
deletion range, so it survives:

```ts
const isOnCorridor = (_corridorName: string, distanceMiles: number) => {
  return distanceMiles === 0;
};
```

Note what that does: it measures nothing. It returns true only when distance is exactly `0`, which
happens solely because `addressMatchesCorridor()` forces it to 0 on a server-side address match.
That is what rescues the on-corridor case — **by raw geometry, Milwaukee Avenue ranks last of six
for an address on Milwaukee Avenue** (0.48 mi to centerline).

**The risk is not loss. It is orphaning.** The boundary survives intact but does nothing unless the
new sections consume it. Three things must carry over:

1. `useCorridorNews(...)` at line **2926** stays.
2. Each section's `.1` subhead filters on non-empty `corridorKeys`; `.2` takes the rest.
3. `isOnCorridor` is used in the culture section's block 1 so the caption reads *on corridor* when
   distance is 0 and *nearest corridor* otherwise.

**Only now, and in a commit of its own.**

block starting at **17718**.

`mergeAccOrder` (line 1262) makes this safe with no migration:

```js
const out = saved.filter((x) => def.includes(x));
```

their placement for that one row. No crash, no orphan row. `accHidden` keys for dead ids are inert.
