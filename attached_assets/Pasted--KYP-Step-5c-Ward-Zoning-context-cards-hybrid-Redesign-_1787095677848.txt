# KYP — Step 5c: Ward & Zoning context cards → hybrid

Redesign the two context cards that sit under the map (above the "Shape your report" setup zone):
**Ward & Alderperson** (`RunDetail.tsx:3733-3827`, `id="print-section-ward"`) and **Zoning Details**
(`RunDetail.tsx:3830-3946`, `id="print-section-zoning-details"`).

up a thin collapsed line ("Leni Manaa-Hoppenworth · Ward 48 — view details") that hides all their
real content behind a chevron. This step gives them a **real collapsed state that carries
information**, and an expanded state in the bold hybrid language.

**Match the attached mock exactly.** No data is added or removed — every existing field is kept.

## 1. WARD & ALDERPERSON card

**Collapsed (default):** crest `{ward}` / "WARD" (indigo) · label "Alderperson" · `facts.alderman` ·
sub-line `**{years} yrs** in office · {attendance} attendance` (omit either half if the field is null;
if both are null, sub-line is the ward office neighborhood or nothing).

**Expanded** — everything currently rendered, in this order:
1. `.kyp-cxrows` — three contact rows, same links/testids as today: phone (`tel:`,
   `link-alderman-phone`), email (`mailto:`, `link-alderman-email`), ward office (Google Maps,
   `link-alderman-office`).
2. `.kyp-cxstats` — two filled blocks: **ind** = `aldermanYearsInOffice` via existing `yearsTile()`
   (`text-alderman-years`), **dark** = `aldermanAttendance` (`text-alderman-attendance`). Keep the
   existing non-numeric fallback ("on City Council").
3. `.kyp-cxcta` → Councilmatic (`aldermanCouncilmaticUrl` w/ existing fallback,
   `link-alderman-councilmatic`). Copy: **"Legislation & donors"** / "Voting record & campaign
   finance · via Councilmatic".
4. `.kyp-cxwtm` "Why this matters" — all **four** existing bullets, copy unchanged.
5. `.kyp-cxlink` → `aldermanUrl`, "View full Ward {ward} page ↗" (`link-alderman-page`).

## 2. ZONING DETAILS card

**Collapsed (default):** crest `{facts.zoning}` / "ZONING" — **indigo, same as ward** · label
"Zoning district" · `zoningInfo.name` · sub-line = allowed categories + FAR, e.g.
`Residential + commercial · **5.0 FAR**` (build from the three booleans + `maxFAR`).

> **The crest is ALWAYS indigo.** A zoning code is a *designation*, not a verdict — it is not
> good or bad on its own (that depends on the user's intended use, which is the Project Type
> section's job). Never color it green/orange/red, and do not wire it to `effectiveCompatibility`.

**Expanded** — everything currently rendered, in this order:
1. **DELETE `zoningInfo.description`** (the "Community shopping districts accommodate…" paragraph).
   It duplicates "What this zoning means" below. This is the only content removed in this step.
2. `.kyp-cxrows` — the three allow-rows **stacked vertically** (not pills), mirroring the ward's
   contact list so the filled blocks align across both cards:
   `✓ Residential` / `✓ Commercial` / `✕ Industrial`, `.on` when allowed. Keep testids
   `badge-residential`, `badge-commercial`, `badge-industrial`.
   Where residential is allowed but not at ground level, append a muted `.note` — "— above ground
   floor" (derive from the same `allowedUses` "above" sniff `zoningMeaningBullets()` already uses).
3. `.kyp-cxtiles` — four filled blocks, values from the existing helpers:
   **ind** Max FAR (`maxFAR`, "floor-area ratio") · **dark** Max Height (`heightTile()`) ·
   **slate** Parking (`parkingTile()`) · **slate** Min Lot Area (`minLotAreaPerUnit`, "sq ft per unit").
   When a value is absent render the word **"None"** + sub "not specified" — never a bare em-dash
   (a dash in a filled block reads as missing data; "None" is a real answer).
4. `.kyp-cxlbl` "Allowed uses — as of right" + `.kyp-cxuses` chips (`badge-use-{i}`).
5. `.kyp-cxwtm` "What this zoning means" — the three existing `zoningMeaningBullets()`.
6. `.kyp-cxfoot` — "Data may not reflect recent rezonings. [Verify on the official map] — search by
   {PIN}" (PIN in `.pin`, same formatting + link as today).
7. `.kyp-cxlink` → Chicago Zoning Code (`link-zoning-code`).
