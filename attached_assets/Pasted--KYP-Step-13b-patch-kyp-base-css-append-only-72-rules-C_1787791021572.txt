## 1. Two things change appearance immediately

This is not inert, and that is intended.

**Subheads change everywhere they already render** — Permits, Transit, Neighborhood News. They become
larger, gain a 1px ink rule above, and the flat divider line disappears. Any existing subhead that
does not yet carry a number will look like a header with a missing number until its section is
updated. That is expected and it is the point: they were getting lost.

**Filled blocks gain breathing room.** `.bl` picks up `margin-top:8px`, `.bd` goes from `2px` to
`5px`. This affects every `.kyp-block` in the app — 23 in `RunDetail.tsx`. It is the crowding fix
that was requested for Historic Status, applied globally as agreed.

## 2. Add the number span to existing subheads

The new form expects an optional `.n` before `.lbl`:

```tsx
<div className="kyp-subhead">
  <span className="n">06.1</span>
  <span className="lbl">What changed</span>
  <span className="ct">optional count</span>
  <span className="rule" />
</div>
```

`.rule` is kept and hidden so existing markup stays valid — do not strip it. **The number must be
derived from the section's live accordion position, not hard-coded**, so it follows when a user
reorders sections. `accProps` already computes `index` and `order`; pass the section's index down and
render `{index}.{n}`.

Do this for the 14 existing `.kyp-subhead` instances in `RunDetail.tsx`.

## 3. What is NOT in this step

`.kyp-zrec`, `.kyp-says` and `.kyp-xfer` are shipped here but **nothing uses them yet**. Zoning
History currently renders in Tailwind utilities and contains zero `kyp-` classes. Rewriting that
section's markup is Step 14b and comes next — do not start it in this step.
