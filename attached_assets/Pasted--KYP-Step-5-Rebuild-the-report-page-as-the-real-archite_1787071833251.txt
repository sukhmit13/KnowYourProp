# KYP — Step 5: Rebuild the report page as the real architecture (NO flags)

This replaces the report page structure itself. **Remove `?scan` and `?hybrid` gating entirely** —
the new layout *is* the page for everyone. The safety net is that the accordion is a pure wrapper:
each section's existing JSX renders inside its row body unchanged, so nothing is hidden or lost —
converted sections show their new design, unconverted sections show today's content inline, and we
keep converting them one at a time on top of this structure.

**Page order (top → bottom):**
1. Address header (declutter — remove the Project Context + Insight Report buttons from here)
2. Meta strip (Neighborhood · Tract · TIF · Zoning · Opp Zone) — as today
3. Map — as today
4. Alderman + Zoning context cards
5. **Shape-your-report** setup zone (3 optional steps + tailoring meter)
6. Instructional bar + legend + reset-order
7. **The sections** — accordion, **default all-expanded**, each row collapses to one line
8. **Generate Insight Report** — moved to the bottom

Do this in the phases below. Each phase is safe on its own; after Phase 6 you can delete the flags.

## Phase 1 — `<AccordionSection>` wrapper component (new file)
`client/src/components/AccordionSection.tsx`. This is the row shell every section goes inside.

```tsx
import { useState } from "react";
type Verdict = "good" | "watch" | "context";
const VCLASS: Record<Verdict,string> = { good:"g", watch:"o", context:"c" };

export function AccordionSection({
  index, id, eyebrow, takeaway, stat, verdict, badge, info,
  defaultOpen = true, onHide, children,
}: {
  index: number; id: string; eyebrow: string; takeaway: React.ReactNode;
  stat?: { n: string; u: string }; verdict: Verdict; badge?: string; info?: string;
  defaultOpen?: boolean; onHide?: () => void; children: React.ReactNode;
}) {
  const [open, setOpen] = useState(defaultOpen);
  const v = VCLASS[verdict];
  return (
    <div className={`kyp-accrow ${v}`} id={`section-${id}`} data-testid={`accsec-${id}`}>
      <div className="kyp-acchd" onClick={() => setOpen(o => !o)}>
        <span className="drag" title="Drag to re-rank" onClick={e => e.stopPropagation()}>⠿</span>
        <span className="num">{String(index).padStart(2,"0")}</span>
        <div className="mid">
          <span className="eb">{eyebrow}</span>
          <span className="tk">{takeaway}</span>
        </div>
        {stat && <span className="stat"><span className="n">{stat.n}</span><span className="u">{stat.u}</span></span>}
        {badge && <span className={`badge ${v}`}>{badge}</span>}
        <span className="ico" title={info} onClick={e => { e.stopPropagation(); /* show info tooltip */ }}>ⓘ</span>
        {onHide && <span className="ico" title="Hide section" onClick={e => { e.stopPropagation(); onHide(); }}>👁</span>}
        <span className="ico">{open ? "⌃" : "⌄"}</span>
      </div>
      <div className={`kyp-accbody${open ? "" : " closed"}`}>{children}</div>
    </div>
  );
}
```
Notes: `defaultOpen = true` → **opens fully expanded**. `id` keeps the existing `section-*` / print
anchors working. Drag/eye are stubbed handlers — wire to the existing reorder + show/hide state
(the scan page already had this logic; lift it here). Info opens the same tooltip the scan page used.

## Phase 2 — Section metadata (one source)
You already derive per-section takeaway/verdict/stat for the scan page (Step 3 `buildScanSections`).
Keep that as the single source and feed it into the wrapper. Each entry needs:
`{ id, order, eyebrow, takeaway, stat?, verdict, badge, info }`. Sections without a real takeaway
fall back to their existing `summary` string (same fallback rule as Step 2). Default order = the
fixed report order (Property Overview → … → News). Reorder/hide state persists as the scan page did.

## Phase 3 — Wrap every section
In `RunDetail.tsx`, the report body becomes a single `.kyp-acc` list. For **each** existing section
block, wrap its current JSX in `<AccordionSection {...meta}>{ …the section's existing content… }</AccordionSection>`.
- **Converted sections** (Crime, News, Incentives, Transit, and any others done): put their `?hybrid`
  branch here as the body, and **delete the `else` (old) branch + the flag check** — the new design
  is now the only render.
- **Unconverted sections**: put their **current** JSX in the body, untouched. They render inline,
  fully, today's look — nothing hidden. We convert them section-by-section later, editing only that
  one wrapper's children.
- Keep every `data-testid`, `id`, and `print-section-*` anchor.

## Phase 4 — Setup zone (3 steps) — wire to existing components
Render `.kyp-setup` above the accordion. Do **not** build new inputs — reuse what exists:

- **Step One · Your intended use** → the existing `ProjectTypeCombobox` + `handleProjectTypeChange`.
  Done-state when `selectedProjectType || run.lastProjectType`: show the use + the zoning verdict chip
  (`effectiveCompatibility.permission === 'permitted'` → "Allowed by right"). Empty-state: the combobox
  + payoff "See if your use is allowed here, and which incentives you qualify for."
- **Step Two · Project Context** → the existing `FunnelModal` (`setShowFunnelEdit(true)`).
  Done-state when `run.lastFreeformDescription || run.lastRole || run.lastTransactionType`: show a
  one-line summary of their answers ("{role} · {transactionType} · saved") + "Edit context". Empty:
  "Tell us your goals — 5 quick questions, skip anytime" + a "Start →" button.
- **Step Three · Your numbers** → the existing valuation calculator (`setIsValuationCalculatorOpen`).
  Done-state when `valuationComplete`: "{price} · {cap}% cap · edit". Empty: "Enter the deal →".
- **Meter**: reuse the InsightReport checklist booleans (`projectTypeComplete`, `contextComplete`,
  `valuationComplete`) → `n of 3 · tailored`, dots filled per complete step.

Each step is optional and never blocks the report.

- Preserve all `data-testid`s, `id`s, `print-section-*` anchors, and the Insight Report / funnel /
