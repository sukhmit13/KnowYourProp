## Part G — accounting format on every numeric input

`parseFormattedNumber` at `valuation.ts:5` strips commas on read; nothing ever writes them. Add
beside it:

```ts
/** Group a numeric input for display. Keeps a trailing "." and any decimals the
 *  user is mid-way through typing, so the caret never fights the formatter. */
export function formatNumberInput(raw: string): string {
  if (raw.trim() === "") return "";
  const negative = raw.trim().startsWith("-");
  const cleaned = raw.replace(/[^\d.]/g, "");
  if (cleaned === "") return negative ? "-" : "";
  const [whole, ...rest] = cleaned.split(".");
  const grouped = whole === "" ? "" : Number(whole).toLocaleString("en-US");
  const decimals = rest.length ? `.${rest.join("").slice(0, 2)}` : (cleaned.endsWith(".") ? "." : "");
  return `${negative ? "-" : ""}${grouped}${decimals}`;
}
```

Apply on change and to seeded values in both field components, and add `num` to the input class:
`<input className="kyp-input num" inputMode="decimal" … />`. Percent and year fields keep `num` so a
row of inputs reads as one column.

Do not add a masking library. If mid-string editing proves awkward in testing, format on blur
instead.

## Part H — every derived income number can be overridden

**This is the rule, and it has no exceptions.** Wherever income comes from an automation — day care
capacity × rate, unit count × market rent, a listing rent roll — the source list's **last option is
`Enter my own`**. The pattern already exists for rent at `ValuationCalculator.tsx:477`; make it
universal. Three states, drawn in `income-source.html`:

**1 · Derived.** The list names the automation. The readout repeats it, carries a `Derived` tag, and
links to the page that produced it.

**2 · Overridden.** Choosing `Enter my own` swaps the readout for a field, and **our estimate stays
beside it** with the variance and a revert button:

```tsx
  <div className="kyp-dealfields two">
    <NumberField label="Annual revenue" value={ownRevenue} onChange={setOwnRevenue}
      tag={<ValuationTag kind="assume">{ownRevenue ? "Entered" : "Unknown"}</ValuationTag>} />
    <div className="kyp-ourest">
      <span className="cl">Our estimate</span>
      <span className="cv">{fmt(derivedRevenue)}</span>
      <span className="cd">{derivedLabel}{ownRevenue ? ` · ${variancePct}` : " · available if you want it"}</span>
      <button type="button" className="kyp-btn ghost sm" onClick={useOurs}>Use ours instead</button>
    </div>
  </div>
```

Two invariants, both testable:
- **A typed value is never silently discarded.**
- **A typed value is never silently overwritten when the automation refreshes** — not when the
  listing updates, not when the building area changes in §17.5.

The variance line is plain text, never colored. A client 8% above us may know something we do not.

**3 · Blank.** An empty override is *unknown*, not zero. NOI renders `—`, nothing downstream
calculates, and our estimate stays one click away.

## Part K — the Simple-tier expense ratio

In Simple, business operating expenses are **a percentage of revenue**, not a dollar figure. Both
tiers must produce the same NOI; there is a test.

The percentage **excludes occupancy, county taxes and building insurance** — the boundary that
keeps the property half and business half from double-counting. Beside it, show the all-in
conversion so an operator can check against a ratio from their own books:

> **67.0% all-in** once county taxes ($21,400) and building insurance ($12,600) are added — compare
> this with a ratio taken from an operator's own P&L, which usually has occupancy inside it.

**Defaults, tagged with their source and editable:**

| Path | Default | Why |
|---|---|---|
| Business only (leases) | **75%** | rent is inside the ratio |
| Business + real estate (owns) | **60%** | rent excluded; the 15-point gap *is* occupancy at 15% of revenue |

Band shown as context, not a target:

> Across **425 day cares sold 2021–2025**, median revenue was **$584,126** against median owner
> earnings of **$132,779** — SDE at **22.7% of revenue**, so expenses ran **77.3%** with rent
> inside. Excluding occupancy that puts this field near **62–68%**.
> *BizBuySell valuation benchmarks, sold listings · SDE is before owner compensation*

Slate, uncolored. Nobody authoritative published cut points, so it cannot be a verdict.

**Debt service is never inside either percentage.** The order is expenses → business operating
income → taxes and insurance → **NOI** → debt service → cash flow. `valuation.ts:189` already does
this; keep it.
