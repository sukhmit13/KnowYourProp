# Replit Prompt — Location-Based Incentives — standardize the whole section — build to spec

Two levels of standardization: **(1)** the section adopts the carded standard (header → takeaway → bucket summary → grouped list), and **(2)** every incentive renders as ONE canonical card with a fixed set of optional slots — sparse and rich cards are visibly the same component. Implement CSS/HTML **verbatim**; check CRITICAL DETAILS.

## 🔴 The core rule — one card, fixed slot order, slots hide when empty
Every incentive card has this anatomy, ALWAYS in this order. A slot with no data is simply omitted — never restyled, never reordered:
```
1. Header      — status icon · name · type tag · status pill        (ALWAYS)
2. Verdict box — tinted by status; bold statement + optional subline (ALWAYS)
3. Key facts   — ONE stat-cell row: flat facts AND schedules/tiers   (optional)
4. Two-column  — Who can apply / Eligibility (or Eligible uses)      (optional)
5. Note        — deadline/cycle, or a caveat (calendar/clock/x icon) (optional)
6. Footer      — program link(s) … source                           (ALWAYS)
```
The difference between a one-line "not applicable" card and the rich Class 7 card is only **how many optional slots are filled** — the header, verdict box, and footer are identical.

## 🔴 Status = 3 states, one color system everywhere
Every card, pill, icon, verdict tint, and bucket maps to exactly one of three states (this is the section's whole favorability axis — legitimate good/neutral/watch coloring):
| State | Meaning | Pills that map to it | Color |
|---|---|---|---|
| `good` | you likely qualify | Potentially Eligible · In Area · Authorized · In Qualifying Zone (eligible) | green `--good`/`--goodSoft` |
| `caution` | needs a manual/human check | Needs Confirmation · Manual Check · In Qualifying Zone (unconfirmed) | marigold `--cautionText`/`--cautionSoft` |
| `na` | doesn't apply | Not Applicable · Not in Zone · Not Eligible | grey `--muted`/`--paper` |

The pill LABEL varies per program; the pill/icon/verdict COLOR is one of these three. Buckets (10/5/32) use the same three colors.

## Section takeaway (Standard component)
3 bullets: (1) `good` — the ONE unlock that matters (e.g. the TIF location → Class 7 / SBIF / CDG), chip → `#relevant`; (2) `insight` — the counts (10 relevant / 5 confirm / 32 n/a) and why the 32 don't fit (residential/affordable programs vs a commercial parcel); (3) `caution` — "potentially eligible ≠ guaranteed; every program needs application + approval; confirm funding cycles." This is the honesty guardrail — see LOGIC 4.

## Grouping
Render three groups in order: **Likely relevant** (good), **Needs confirmation** (caution), **Not applicable** (na); within each, order by type (Property Tax → Financing → Grants → Tax Credit → Zoning). Each group gets a `.grouph` with its count. The 32 `na` cards may default-collapse to header-only rows (name + pill), expandable — but the expanded card uses the SAME anatomy.

## LOGIC
1. **Fixed slot order, hide-when-empty** — never reorder or restyle a slot because a card is sparse. Header + verdict + footer always; slots 3–5 (key facts, two-column, note) only when data exists.
2. **One 3-state color system** — `state` drives icon, pill, verdict tint, and bucket color. The pill label is free text; the color is not.
3. **One number component, always** — flat facts (Term / 16%), year schedules (10/15/20 over years), and grant tiers (Small/Medium/Large) ALL render as the SAME `.kf` stat-cell row (mono label · serif value · optional detail). Never two different components for numbers — that's the exact drift that made Class 7c look different from Class 7(a)/(b). More/fewer cells, same cell.
4. **"Eligible" is never a promise** — every `good`/`caution` card's verdict is phrased as *potentially* eligible / in a qualifying zone, and (where it applies) carries the "requires application — not automatic" note. Never state a program as granted.
5. **`na` verdict states the missing condition** + the standard "the available location data does not establish eligibility" subline. No apology, no green.
6. **Links + source always in the footer** — program link(s) left, source right. Consistent across all 47.

## CRITICAL DETAILS
1. **One canonical card, fixed slot order, slots hide when empty** — sparse vs rich differ only by filled slots.
2. **Three states, one color system** — good/caution/na drive icon+pill+verdict+bucket; pill label varies, color doesn't.
3. **One stat-cell component for ALL numbers** (facts, schedules, grant tiers) — no per-program bespoke layouts; sibling programs (Class 7c vs 7a/b) must render numbers identically.
4. **Section = carded Standard Structure** (header → takeaway → buckets → grouped list); takeaway is the shared component.
5. **Eligibility is always conditional** ("potentially", "requires application"); `na` uses the standard subline; no program shown as guaranteed.
6. **Serif (`--disp`) ONLY** on the takeaway headline, the bucket numbers, and the stat-cell value (`.kfc .kv`). Everything else Inter/Mono.
