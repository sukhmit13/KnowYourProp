## Rules that apply to all three prompts

1. **No takeaways.** Delete every sentence that tells the reader what the data means. Numbers,
   classifications from an outside authority, and sources stay. Judgements go.
2. **Scope and source notes go at the END of each subsection, once**, in a `.kyp-src`. Never above
   the data, never between panels.
3. **Chart forms do not change.** A line chart stays a line chart.
4. **Verdict colour needs an outside authority.** Green = good, orange = watch, red = bad,
   slate = context, indigo = no claim. If the cut points are ours, the footer says so.
   A rank is context and takes slate, never a verdict colour.
5. **Do not invent CSS.** Everything needed is in `kyp-base.css` plus the patch file.
6. **Do not label a chart with what the chart already draws.**

## 3. One scope control, not three

There are three today:

| Panel | Line | Pattern |
|---|---|---|
| Grocery Access | `7188` | `<Tabs defaultValue="zip">` — **uncontrolled**, resets on re-render |
| Senior Population | `7583` | controlled by `seniorsViewMode` |
| Childcare (×3 strips) | `3860`, `6279`, `6898` | `childcareViewMode`, written by 2 panels, read by 5 |

Replace all of them with **one control at the top of the section body**, before the first
subhead, reading and writing a single `useState<'zip'|'community'>('zip')` named `areaViewMode`.
Delete `seniorsViewMode` and `childcareViewMode`.

```jsx
<div className="kyp-segrow">
  <div className="kyp-seg">
    <button className={areaViewMode === 'zip' ? 'on' : ''} onClick={() => setAreaViewMode('zip')}>
      ZIP {facts?.zipCode}
    </button>
    <button className={areaViewMode === 'community' ? 'on' : ''} onClick={() => setAreaViewMode('community')}>
      {facts?.communityArea}
    </button>
  </div>
  <div className="spacer" />
  <div className="kyp-scopenote">
    ZIP <b>{facts?.zipCode}</b> · Neighborhood <b>{facts?.communityArea}</b>
    {facts?.ward ? <> · Ward <b>{facts.ward}</b></> : null} — boundaries differ
  </div>
</div>
```

Render it **only** when at least one subsection on screen is area-scoped (childcare, grocery,
seniors). A Bar / Tavern report has nothing area-scoped, so it shows no control — see
`bar-target.html`.

## 4. One competitor row, replacing five

Today there are five row shapes. See `PROJECT_USE_ANALYSIS_MATRIX.md` for the table. All five
become `.kyp-biz-card`:

```jsx
<div className="kyp-biz-card">
  <div><b>{name}</b><a href={mapsUrl} target="_blank" rel="noopener noreferrer">{address}</a></div>
  <span className="kyp-biz-distance">{distance != null ? `${distance.toFixed(1)} mi` : 'distance unknown'}</span>
  {meta.length > 0 && (
    <div className="kyp-biz-cardmeta">{meta.map((m, i) => <span key={i}>{m}</span>)}</div>
  )}
</div>
```

`meta` carries whatever that source actually has and nothing more — `★ 4.4` and `3,210 reviews`
for Google Places, `52,000 sq ft` for grocery, the licence category where there is one, nothing
for a plain licence list.

### Every row links to that business on Google

The **name** carries the link, the address is plain text, so there is exactly one anchor per row.

Two link grades, both already in the codebase:

| Grade | When | URL |
|---|---|---|
| **place page** | the payload carried a Google `place_id` | `https://www.google.com/maps/place/?q=place_id:{placeId}` — already built server-side at `server/google-places.ts:100` and returned as `url` |
| **Maps search** | no `place_id` — every licence-derived list | `https://www.google.com/maps/search/?api=1&query={encodeURIComponent(`${name}, ${address}, Chicago, IL`)}` — the pattern already used at `:7040`, `:14349`, `NewBusinessLicensesSection.tsx:99` |

```jsx
const placeUrl = p.url
  ?? `https://www.google.com/maps/search/?api=1&query=${encodeURIComponent(`${p.name}, ${p.address}, Chicago, IL`)}`;
…
<a className="nm" href={placeUrl} target="_blank" rel="noopener noreferrer">
  <b>{p.name}</b><span className="ext" aria-hidden="true">↗</span>
</a>
<span className="addr">{p.address}</span>
```

`google-places.ts:100` returns `url: null` when Google gives no `place_id`, so **always fall
through to the search URL** — never render a dead or missing link.

Each footer states which grade that list uses. A Maps search is not the same promise as a place
page, and saying so costs one clause.

> **Do not nest anchors.** The row is a `<div>` and only the name is a link. An `<a>` containing
> an `<a>` is auto-closed by the browser, and every element after it loses its styling.

## 5. One distance convention

Three conventions today: 1/2/3-mile triples, a single 1-mile chip (Restaurants, Coffee), and a
ZIP-scoped count (Cannabis). Use one `.kyp-blocks` row of `.kyp-block.slate.count` everywhere the
data supports it:

```jsx
<div className="kyp-blocks">
  <div className="kyp-block slate count"><div className="bv">{within1}</div><div className="bl">Within 1 mile</div></div>
  <div className="kyp-block slate count"><div className="bv">{within2}</div><div className="bl">Within 2 miles</div></div>
  <div className="kyp-block slate count"><div className="bv">{within3}</div><div className="bl">Within 3 miles</div></div>
</div>
```

Where a source is genuinely ZIP-scoped (Cannabis), show one block labelled
`In ZIP {facts?.zipCode}` rather than faking a radius.
