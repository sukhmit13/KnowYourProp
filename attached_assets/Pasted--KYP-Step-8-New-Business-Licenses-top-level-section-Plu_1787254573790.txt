## 1. Server — `server/businessLicenses.ts`

### 1A. Pull 24 months, return both periods
`fetchRecentLicenses()` hardcodes `cutoff.setMonth(cutoff.getMonth() - 12)` (`:85`). Change the
window to **24 months** and split it:

- **current** = licenses with `license_start_date` in the last 12 months
- **prior** = licenses with `license_start_date` in months 13–24

Extend `NearbyLicensesResponse`:

```ts
export interface NearbyLicensesResponse {
  licenses: NearbyLicense[];        // current period only — unchanged shape
  totalCount: number;               // current period licenses
  radiusMiles: number;
  periodMonths: number;
  priorPeriodCount: number | null;  // NEW — distinct businesses in months 13–24
  changePct: number | null;         // NEW — null when priorPeriodCount is 0 or unknown
}
```

**Count businesses, not licenses, on both sides.** The comparison must use the same
establishment grouping the UI uses, or "up 64%" will be measuring the wrong thing. Move
`groupLicenseEstablishments` (currently `RunDetail.tsx:106–131`) and `normalizeLicenseAddr`
(`:64–82`) into shared code and call the same function for both periods. Do not reimplement.

`changePct = null` when `priorPeriodCount === 0` — a rise from zero is not a percentage.
Render "first openings on record in 2 years" instead.

**Cache note:** `cachedLicenses` is a module-level, city-wide cache with a 6h TTL (`:39–41`).
Doubling the window doubles the payload of that one fetch, not per-property work. Keep the
6h TTL. If the fetch time regresses noticeably, cache the two periods separately rather than
shortening the window.

### 1B. Fix the log line
`:145` logs `…(last 6 months)` while the cutoff is 12. Make it print the real window.

### 1C. Radius disagreement
`routes.ts:9066` passes `1.0`; `reportPdf.ts:261` takes the function default `0.5`. Same
property, two different numbers on screen vs in the PDF. **Pass `1.0` explicitly in both.**
While you're there: `reportPdf.ts:612` reads `d.licenses.count ?? …` — `count` does not exist
(it is `totalCount`), so the `??` always falls through; and the copy says "active business
licenses" when these are **new issuances**. Fix both.

## 6. 🔒 Colour — encodes the CLAIM, never the category

| Block | Fill | Rule |
|---|---|---|
| **{n}** New businesses — up/down {p}% | `grn` when `changePct > 0` · `att` when `< 0` · `ind` when **null** | judged against the prior 12 months |
| **{n}** Serve food — {p}% of openings | **`ind` always** | composition, not quality — no verdict is possible |
| **{d} mi** Nearest opening | `grn` when `≤ 0.25` · `ind` above that | distance is judgeable on its own scale |

- Sub-line on the food block must say **"no verdict — depends on your use"**. A food-led
  corridor is amenity to a residential buyer and competition to a restaurant buyer.
- **Chart bars are `ind`, always.** They report counts. A verdict colour never sits on a mark
  that is only reporting a quantity.
- Two green blocks is correct when two numbers are good. **Do not spread verdicts for visual
  variety.**
- No near-black block, no light-wash block, no `.dark`, no `.wash`. Every block saturated.

## 7. 🔒 Gated logic

1. **Trend verdict** — render the `— up/down {p}%` suffix and the coloured block **only** when
   `changePct != null`. When `priorPeriodCount === 0`, the block is `ind` and the sub-line reads
   "first openings on record in 2 years".
2. **Nearest-opening block** — render only when there is ≥1 opening. With zero, the section
   shows the empty state and no blocks at all.
3. **Narrow bars** — `narrow` when a bar is < 15% of the max.
4. **Filter + show-more interaction (currently broken).** With `licenseFilter !== null` the
   6-item cap is bypassed **and** both show-more/show-less buttons are suppressed (`15616`,
   `15699`, `15702`), so a filtered result of 80 renders 80 rows with no control. Apply the cap
   and the buttons **regardless of filter state**, and reset `showAllBiz` to `false` whenever
   the filter changes.
5. **Loading is not empty.** There is no `isError` branch (`15574–15713`); a 500 renders "No new
   business licenses found within 1 mile." Add an explicit error state.
6. **Mix rows** — no cap today, and up to 2⁶−1 = 63 combination labels are possible. Cap at 8
   rows plus a `+{n} more combinations` line. **Never truncate silently.**

## 8. Bugs found while mapping — fix 1–3, log the rest

1. **`Compare.tsx:2170` renders the literal word "Business" for every row.** It reads
   `l.doingBusinessAsName || l.legalName || 'Business'`; neither field exists on `NearbyLicense`
   (it is `businessName`). Masked by `useQuery<any>` at `use-runs.ts:3148`. **Type the hook.**
2. **Corridor Intelligence asserts a false negative while loading.** `18760`, `18899` and the
   KPI all read `nearbyLicensesData?.licenses?.length` with no `isLoading` guard, so
   `CorridorIntelligenceView.tsx:132` prints *"No new business licenses recorded… a quiet
   formation period"* during the fetch, then flips. Guard it.
3. **Two dedup keys for the same records.** This section groups on
   `NAME|normalizeLicenseAddr(address)` (`:109`); Corridor Intelligence groups on
   `NAME|||RAW_UPPERCASE_ADDRESS` (`18905`). The same business at "1234 N Ave Ste 2" counts once
   here and twice there. **Corridor must call the shared grouper** from §1A.
4. `RunDetail.tsx:88` — `.replace(/(st|nd|rd|th)$/, m => m)` is a no-op. Dead code.
5. `RunDetail.tsx:2371` — `isOnCorridor` is `(_name, d) => d === 0`, exact float equality on a
   distance, first parameter ignored. Every `onCorridor` takeaway branch is unreachable.
6. `RunDetail.tsx:122–124` — two unmapped categories both render as `Other`, producing the label
   `"Other + Other"`.
7. Parent proximity takeaway (`15098–15106`) counts only liquor/food/entertainment/manufacturing
   — a corridor of new galleries reads as having no categories.
8. `latitude`/`longitude` are on the wire and copied into `corridorLicenseMap` (`18917`) but
   never read. There is no map. Either build one or stop shipping the fields.
