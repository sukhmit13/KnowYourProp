## LOGIC
1. **Currency vs. verification are separate** — top block = "how current" (status + evidence); bottom block = "how to verify" (seller-side caveat + cross-check links). Never merge them, never repeat either.
2. **`why_historical` is currency EVIDENCE, not a listing highlight** — pull the "no newer listing found / now occupied by a business" findings OUT of the highlights and into the `.stale` note under the status. Highlights carry only the seller's own claims.
3. **No "Disclosed by seller" block** — those facts are already in the highlights; render them once.
4. **Status pill reflects reality** — `delisted`/`none` → grey neutral pill (not red/green; delisted isn't good/bad). If a genuinely `active` listing exists, the headline changes to the active copy and the pill can read "Active."
5. **Attribute conflicting figures** — when two sources disagree (list $599K per Realty.com vs. $557K sale per @properties), show both with their source on the tile `.sub` / a highlight; never silently pick one.
6. **Re-check is a control**, not decoration — wire it to re-run the listing fetch; show the new `checked_date` on success.

## CRITICAL DETAILS
1. **Two caveats, each once** — currency at top, verification at bottom; delete the duplicate top disclaimer and the duplicate seller box.
2. **Carded Standard Structure** — section header (indigo square) + status pill; all content inside the `.seccard`.
3. **Verify box is the clean amber caution** (near-white fill + marigold left rail + `#b26c07` text) — never beige/brown; cross-check links live inside it.
4. **Currency evidence** (`.stale`) sits with the status, not in the highlights.
5. **Serif (`--disp`) ONLY** on the three tile values. Everything else Inter/Mono.
6. **No takeaway box** — the currency status IS the section's headline; adding a takeaway would duplicate it. (If a takeaway is later wanted for visual parity, keep it to the *building summary*, not the currency/verify caveats.)
