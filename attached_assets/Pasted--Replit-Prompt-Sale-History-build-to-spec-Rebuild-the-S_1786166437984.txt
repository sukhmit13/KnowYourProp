## LOGIC (derived — compute in code, NOT the takeaway/LLM engine)

### 1. Ordering & the journey
- Journey strip: **oldest → newest, left → right**. The single newest node gets `class="jn now"` (indigo). `{PRICE_SHORT}` = abbreviated ($350K, $1.19M).
- Card lists: **newest → oldest**. The newest sale is pulled OUT into the `.sale.recent` block; all others render as `.sale` under "Earlier transfers."

### 2. Recorder-of-Deeds freshness flag
- If the most recent sale was found via the **Recorder of Deeds** (not yet in the Assessor dataset), set `{SOURCE}`="Recorder of Deeds", render the takeaway freshness bullet, and render the info-circle freshness caveat under the recent card. If the newest sale IS already in the Assessor data, set `{SOURCE}` accordingly and OMIT both the freshness bullet and that caveat.

### 3. Approximate dates
- If a record only has month/year precision (day missing or defaulted to the 1st), render `{DATE_OR_APPROX}` = "{YEAR} · month approx." Full dates render normally ("Nov 9, 2016"). Any approximate date present → include the "some older dates are recorded only to the month or year" clause in the bottom caveat.

### 4. Non-arm's-length signals (drive the `.naflag` and the `.deed.trust` styling) — **compute in code from record fields, do not free-form with an LLM**
Fire a `.naflag` on a transfer when ANY of:
- **Deed type is a Trustee's Deed / trust conveyance** → also add class `trust` to its `.deed` chip; reason: "Trust conveyance — may not be an open-market sale."
- **Grantee (or grantor) is a land-trust/bank-trust entity** (name contains "Trust", "Bank & Trust", "as trustee", "land trust") → reason: "Into a land trust — likely a title transfer, not a sale."
- **Price is non-monotonic vs. an adjacent later sale** (this sale's price > a later sale's price, unusual) → reason: "Higher than the {later year} price — possible non-market transfer."
- **Grantor and grantee are related entities** (normalized names share the parcel token, e.g. both contain "2540") → reason: "Transfer between related entities."
Only the FIRST matching reason needs to show per card (keep it to one `.naflag`). Never use red for these — `--cautionText` amber only. A flagged sale is "interpret carefully," not "bad."

### 5. Institutional / non-profit buyer note
- If the most recent grantee name matches institutional/public/non-profit patterns (contains "Program", "Authority", "City of", "Corporation" + "not-for-profit", "Church", "Foundation", "Health", "Housing Authority", etc.), render the takeaway bullet 3. Frame it as **"can change use/tax status — confirm in Property Tax,"** never as a definite tax outcome. If the buyer is an ordinary person/LLC, omit this bullet.

### 6. Value-add note (ties Sale History to Permit History) — **the fix for "the timeline looks like pure appreciation"**
- Query the same permit dataset used by the DOB section. If total permitted declared value between the first and last sale exceeds a threshold (e.g. ≥ $50K), render BOTH the takeaway `.i` bullet and the `.jnote` under the journey.
- `{TOTAL_PERMIT_VALUE}` = summed declared value; `{WORK_SUMMARY}` = the 1–2 biggest jobs in plain words (e.g., "a 2012 gut rehab plus 2016–17 porch & electrical"). Both link to `#permits`.
- If there's no meaningful permitted work, OMIT the value-add bullet and the `.jnote`, and the journey may read as market movement — but STILL keep the arm's-length caveat.
- **Never present the price climb as clean appreciation when permitted work exists.** This is the whole point of the note.

## CRITICAL DETAILS (check ALL)
1. **Journey connecting line is `.journey::before`** — absolutely positioned, `left:14px; right:14px; top:31px; height:2px`, behind the dots. The `.jn` items are `position:relative; z-index:1` so dots sit ON the line; each dot has a white/paper fill so the line doesn't show through. Do NOT draw the line with borders on the nodes.
2. **Journey = oldest→newest (left→right); only the newest node has `now`** (indigo price, filled indigo dot, bold indigo year). Cards = newest→oldest.
3. **`.jnote` value-add note renders whenever permitted work exists between sales** — it's what stops the strip from reading as pure appreciation. Wrench icon, links to `#permits`.
4. **Serif (`--disp`) only** on takeaway headline, `.jn .p` prices, and `.sprice`. Everything else Inter; labels/dates/doc#/deed chips are Mono.
5. **The most recent sale is a separate `.sale.recent` card** with indigo left border (`border-left:3px solid var(--indigo)`), `#fbfbfe` bg, and the `.schip` "Most recent" pill. It sits under the `id="recent"` divider (jump target).
6. **Freshness = info-circle caveat, NOT the triangle**, and it renders ONLY for a Recorder-of-Deeds fallback sale. Amber styling, but it's the standard `.caveat` — do NOT tint the whole recent card amber.
7. **Non-arm's-length flags are DERIVED in code** (deed type, trust/entity names, non-monotonic price, related-entity match) — see LOGIC 4. One `.naflag` per card max, amber (`--cautionText`), never red. Trustee's deeds also get the `.deed.trust` amber chip.

9. **Approximate dates** show "{YEAR} · month approx." and trigger the date clause in the bottom caveat.

11. **Bottom `.caveat.mt` (triangle)** summarizes the data-quality picture (land trusts / trustee's deed / related entities / approximate dates) and renders when any of those conditions exist.
12. **All prices right-aligned parties** (`.sparties`, `text-align:right`, `max-width:330px`) so long entity/program names wrap cleanly against the right edge.
