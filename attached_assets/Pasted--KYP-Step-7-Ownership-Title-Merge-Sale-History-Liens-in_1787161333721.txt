## 0. Why these two merge

They are one dataset rendered by two owners, and the seams are shipping bugs:

- Sale History already renders lien data — it takes `lienData.deeds`, picks the newest, and unshifts it into the sales list as a synthetic row (`10846–10863`).
- Liens already renders sales data — `lienDistress` resolves against `pinLookupData.saleHistory` (`1808–1817`).
- The server can't compute debt without sales — `debtReadWindow.ts` keys the OCR window to the most recent genuine sale.
- Three separate join implementations exist because each section keeps reconciling the other's data (`10760`, `10778–10795`, `10841`).

## 2. Server changes — three, all small

### 2A. Hoist the blanket/PIN derivation off `active` — **required for the timeline**
`server/debtResolveState.ts:319` runs `for (const m of active)`. A **released** loan therefore never gets `blanket` / `blanket_pins` computed. Without the old loan's PIN set you cannot detect that the debt's parcel scope narrowed.

Change the loop to run over **every reconciled mortgage** (active + cleared + satisfied), not just `active`. Nothing else in that block depends on liveness. Keep the PIN normalization exactly as written (`normPin`, 10→14 digit padding) — it is correct and load-bearing.

### 2B. NEW — parcel scope change
After 2A, walk the first-position chain oldest → newest. Where consecutive loans have different PIN sets, emit:

```ts
scopeChanges: Array<{
  atDocNumber: string;      // the loan that narrowed/widened
  recordingDate: string;
  droppedPins: string[];    // in the older loan, not the newer
  addedPins: string[];
}>
```

Emit **nothing** when PIN sets are equal, or when either side's set is empty/unknown. An empty set is missing data, not a release.

### 2C. NEW — cash-out classification
The code already classifies refi-vs-junior (`debtResolveState.ts:249–262`). Add, on the **newer** loan of a refi pair:

```ts
cashOutSuspect: boolean;   // newer.effective_amount > older.effective_amount * 1.05
recordedDelta: number;     // newer - older, only when both are known
```

**`cashOutSuspect` never asserts cash taken out.** Recorded amounts are original principal; the older loan had amortized, so the true extraction is *larger* than `recordedDelta` and unknowable from public record. Copy must say "recorded amount rose by $X," never "took out $X." The caveat in §4 is mandatory whenever this renders.

## 5. The document reference — kills five formats

A recorded document number renders **five different ways** today:

| Where | Renders as | Linked |
|---|---|---|
| `RunDetail.tsx:10934` | `Doc #1307145022 ↗` | yes |
| `RunDetail.tsx:12051` | `2116922041` | yes |
| `RunDetail.tsx:12217` | same, **builds its own URL inline** | yes |
| `shared/debtCardModel.ts:200` | `mortgage 2116922041` | **no** |
| `shared/debtCardModel.ts:302` | `recorded 8/28/2025 · doc 2524011012` | **no** |

Replace all five with one helper. Document number and recording date come from the same index row and always render together, in this order, always linked:

```jsx
function DocRef({ documentNumber, viewLink, recordedDate, dateIsApprox, releasedBy }) {
  const url = viewLink || `https://crs.cookcountyclerkil.gov/Search/ResultByDocNum?id1=${documentNumber}`;
  return (
    <div className="kyp-docref">
      <span className="k">Document</span>
      <a href={url} target="_blank" rel="noopener noreferrer">#{documentNumber} ↗</a>
      <span className="sep">·</span>
      <span className="k">Recorded</span>
      <span className="v">{recordedDate}</span>
      {dateIsApprox && <span className="approx">· day not recorded</span>}
      {releasedBy && <>
        <span className="sep">·</span><span className="k">Released by</span>
        <a href={releasedBy.url} target="_blank" rel="noopener noreferrer">#{releasedBy.documentNumber} ↗</a>
      </>}
    </div>
  );
}
```

Rules: **never** plain text, **never** a hand-built URL outside this helper, **never** a per-section format. It is the footer of every `kyp-xact` — both sales, all loans, every lien and filing. A release reference gets the identical treatment because a release *is* a recorded document.

Consequence: pull `Recorded` out of the loan terms grid (it lives in the footer now), leaving three clean terms — rate, maturity, position.

## 6. 🔒 Gated logic — render only when the condition holds

### 6.1 Timeline
Render **only** when any of:
- `timelineEvents.length >= 3`, **or**
- any loan has `refi_suspect` or is the newer half of a refi pair, **or**
- `scopeChanges.length > 0`.

Otherwise omit the chart *and* its title entirely. A single sale plus a single mortgage is two dots and a straight line — decoration. Most single-parcel properties will not render it, and that is correct.

### 6.2 Parcel coverage band (inside the timeline)
Render **only** when at least one instrument in the chain names a PIN other than the subject (`blanket_pins.length > 0` on any loan, post-2A). Otherwise the timeline is spine-only and shorter. Never render a one-row band.

Row per PIN, subject first. A row is cyan where that PIN is named by an unreleased loan, green from the recording date of the instrument that dropped it (from `scopeChanges.droppedPins`), otherwise empty track.

### 6.3 Cash-out annotation + caveat
Render the `+$X recorded` step **only** when `cashOutSuspect === true` **and** both amounts are known. Whenever it renders, the caveat below the chart is **mandatory and not dismissable**:

> The 2021 loan is $352,500 larger than the one it replaced — but that is not the cash taken out. The older loan had been amortizing, so its payoff balance was below its original amount, and the true cash-out is larger than the gap shown. Recorded amounts are the only figures Cook County publishes.

If the caveat is ever suppressed, suppress the annotation too. They ship together.

### 6.4 Before-you-close callout
Render **only** when an unreleased junior lien or unreleased revolving line exists — `active.some(m => (m.lien_kind === 'junior' || m.revolving) && !m.satisfied)`. Never for a released one. It carries the **consequence**, never a restatement of the amount (the block already has that).

### 6.5 Borrowed-block breakdown rows
- `active.length <= 1` → no breakdown; sub-line is that loan's terms (`3.125% · matures 2051`).
- `active.length` 2–3 → one row per loan: amount + kind + key terms.
- `active.length > 3` → top 3 by amount, then `+{n} more` — and `log`/render that count, never silently truncate.

### 6.6 Runway bar
Render **only** when the loan is active **and** `!revolving` **and** `effective_maturity_date` is known **and** `maturity_source !== 'estimated'`. A revolving line never gets one — `debtMaturityEstimate.ts` already refuses to assign a maturity when `is_credit_line`, and there is a test asserting it. Do not work around that.

### 6.7 Rate & maturity by extraction confidence — **my call, override if you disagree**
`extraction_confidence` is `high | medium | low`, and `recorderDocIngest.ts:197` defines low as "OCR text is garbled/sparse."

| Confidence | Render |
|---|---|
| `high` | value plainly |
| `medium` | value + sub-line "· read from a scanned image" |
| `low` | **suppress the value.** Show `Not legible on the recorded document` in `.tv.na` |

Rationale: a garbled rate is worse than no rate — someone will underwrite off it. Medium is worth showing hedged.

### 6.8 Blanket flag on a loan card
Render the `Blanket · {pins}` chip and the explanatory `xflag` **only** when `blanket === true && blanket_pins.length > 0`. When `blanket` is true from the **soft** value heuristic (`debtResolveState.ts:331–333`, amount >> parcel value) with no other PIN, say "may be cross-collateralized — confirm", not "blanket."

### 6.9 Prior-owner debt line
Render **only** when `cleared_by_sale.length > 0`. Copy: "N mortgages recorded against {prior owner} before {date} are treated as resolved at the {year} closing. They are not counted in the totals above." This exists so the reader knows debt was *excluded*, not missed.

### 6.10 Chain-of-title arm's-length flag
Keep the existing `naflag` heuristics. Render the flag per sale, not once per section.

### 6.11 Title status
- `activeLienCount === 0 && no active filings` → the green statement sentence, then any **historical** filing as a muted `kyp-xact.claim` with a "Resolved by the {year} sale" tag.
- otherwise → one card per active lien, `bad` rail, no statement sentence.

## 7. Guardrails

- **Never put two kinds of money in one column.** Purchase price is `PAID`, mortgage is `BORROWED`, lien is `CLAIMED`. Sale prices are MyDec/PTAX-203 declared transfer amounts from the **Assessor**; loan amounts come from the **Recorder**. They are different records and must never be summed, compared as like-for-like, or share a visual treatment.
- **Cyan is a category, not a verdict.** `--kyp-debt` never appears on a verdict pill, never gets an orange/red counterpart, never means "bad." Debt is not a judgment. Validated at normal ΔE 18.5 vs indigo and 17.2 vs verdict green, deutan 15.6 — do not re-step it by eye.
- **Never render an amount as a balance.** Every loan figure is original recorded principal. Cook County does not publish balances. A revolving line's amount is *maximum indebtedness*, not what is drawn — label it as such every time.
- **Do not change** `saleVM`, the `professionals` aggregation, `resolveDistress`, or the reconcile/resolve pipeline beyond §2. Those are correct.
- Three blocks. Always three. Not four, not two.
- One title, one ~70-char takeaway, one badge — all in the row header.

## 8. Bugs found while mapping — fix these, they are cheap

1. **Foreclosure banner and chip disagree.** Banner (`11490`) uses `lienData.hasForeclosure` (server heuristic); chip (`11447`) uses `lienDistress.hasForeclosureActive` (resolved against sale history). A property with a CCAO sale after the filing renders "Active foreclosure — title is clouded" and "Clear title" simultaneously. `shared/lienDistress.ts:11-13` claims they cannot disagree — the banner was never migrated. **Use `lienDistress` everywhere.**
2. **"Most recent deed" picked three ways.** `8467` takes first-in-array, `10749` sorts descending, `11328` is a third path. Header badge, takeaway bullet, and sale card can quote different deeds. **One derivation, sorted by `recordedDate` desc.**
3. **Two arm's-length definitions.** Client `naflag` (`10865–10872`, four heuristics) vs server `debtSnapshot.ts:129` (`price > 1000 && !quitclaim`). **Server should consume the client rule**, or both should call one shared helper.
4. **Co-parcel Lis Pendens KPI is a different formula** — `12338` computes `foreclosures.length + (activeListPendensCount ?? litigation?.length ?? 0)`, counting foreclosures as lis pendens and including released filings; the primary card uses `lienDistress.lis.activeCount`. Moot once the block is deleted, but do not carry the formula forward.
5. **Scrape failure is indistinguishable from clean title.** `routes.ts:6398–6421` returns a stub on 500 with `overallStatus:'unknown'`, which renders **no badge at all**, and `12110` says "No mortgages, liens, or other encumbrances found." **Add an explicit error state** — absence of scrape is not absence of encumbrance.
6. **Pooled LTV is permanently unreachable.** `1855–1857` builds `coParcels` with no `estimatedValue`, but `buildDebtSnap` requires it (`debtSnapshot.ts:161`), so `pool_ltv` is always null and the cell always renders "—". Either populate the value or drop the cell — do not ship a feature that can never fire.
7. **Optimistic cache write never lands.** `use-runs.ts:1746` writes a 3-element query key; `useLienSearch` registers a 4-element key (`:1676`). Harmless but dead.
8. **Five client/server type mismatches** absent from `shared/schema.ts` but produced by the server and read by the client: `isProbablyCleared`, `isWaterDept`, `maturityDate`, `activeListPendensCount`, `waterDeptLienCount` (the last is never read at all). Add them to `LienDocument`/`LienResult` so `PreTitleCheck.tsx:31` can stop typing the whole prop `any`.
9. **Delete the co-parcel liens block** (`12287–12469`) — a near-complete Tailwind duplicate of the primary card with **no testids anywhere** and its own divergent KPI math. The co-parcel is covered by the parcel coverage band and the blanket chips.
