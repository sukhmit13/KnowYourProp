## LOGIC (derived — compute in the backend / code, NOT the takeaway engine)

### 1. Owner-era split (the key derivation)
- Input: `last_sale_date` (most recent recorded sale) and each record's date.
- For each **permit**: `era = (permit.issue_date >= last_sale_date) ? "current" : "prior"`. Same rule for each **violation** (by issue date).
- Era chip: current → `era cur`, label "Current owner"; prior → `era prior`, label "Prior owner". **This is categorical, not favorability — never color it green/red.**
- Group permits under two dividers: **"Under current ownership"** (meta: `since {sale month/yr}`) then **"Under prior ownership"** (meta: `before {sale month/yr}`). Each divider's meta shows that group's permit count + summed declared value.
- **Edge case — sale predates all permits:** the current-ownership group is empty. Render the current divider followed by a single muted line `No permits pulled under current ownership.` (don't render an empty group with no rows). Symmetric case (all permits current) → omit the prior group entirely.
- **Edge case — no sale date on record:** skip the era split entirely (one ungrouped, newest-first list), drop all era chips, and change `.basis` to note the split couldn't be computed. Never guess an era without a sale date.

### 2. Permit effective status
- `complete` (green `st complete`, "Complete") when the permit is closed/finaled.
- `expired` (amber `st expired`, "Expired · not closed") when the permit lapsed without a recorded final/close-out. **Amber caution, NOT red** — an open permit is a loose end to verify, not a serious defect.
- Header mini-flag `{N} permit not closed out` appears only when ≥1 permit is `expired`; hide it otherwise.

### 3. Permit scope wording
- `{PERMIT_SCOPE}` may echo the permit's own description field **verbatim** (city record). But any text WE author (takeaway, professional summaries) must NOT assert a unit count — describe at the building level ("entire building"). Unit count is owned solely by the Parcel section.

### 4. Professional data source & aggregation
- **Source:** architect and contractor names come from the **city/county permit API**, per permit. This is authoritative for who worked on THIS property (the "Here" line binds directly from it). The citywide stats and MBE/WBE status are SEPARATE joins layered on top (see §5–§6).
- **List EVERY professional on the building — no top-N, no truncation.** The purpose is to give the user a complete starting point, not a ranked shortlist. If a permit lists 6 firms, all 6 appear.
- **Role-agnostic.** Support any professional role the permit data carries — architect, general contractor, and trades (electrical, plumbing, mason, etc.). Role-tag color = **design professional (architect/engineer) → `p2role arch` (indigo); any contractor/trade → `p2role gc` (warm grey)**; the specific role goes in the label text (`{ROLE_LABEL}`, e.g. "Electrical contractor", "Mason").
- **Deduplicate by firm**, keyed on license number when the permit record includes it, else normalized name. One row per firm, aggregating: permit count on this property, summed declared value, most-recent year, short scope phrase.
- **Sort: each firm's most-recent permit year, descending.** Tie-break design-professional-before-contractor.
- Era chip on each firm = the era of their most-recent permit here.
- Every firm's "Here" line ALWAYS renders (it's straight from the permit API); only the `.p2cite` citywide line and the `.cert` chips are conditional on a confident match.

### 5. Match key (governs BOTH citywide stats and MBE/WBE)
- **Preferred join = IL license number.** Use it whenever the permit record exposes it.
- **If the permit API returns only a name string** (no license number), fall back to a **normalized-name match with a confidence threshold**. Below threshold = treat as NO match: suppress the citywide `.p2cite` stats (show the `.nomatch` line) AND omit the `.cert` chips. Never attribute another firm's stats or certification on a weak name match.
- A firm can therefore appear with its property record only, no enrichment — that's the correct, safe outcome, not a bug.

### 6. MBE/WBE certification
- **Source:** the City of Chicago certified-firm directory (MBE = Minority Business Enterprise, WBE = Woman Business Enterprise; DBE if present). Join by the §5 match key.
- Render a `.cert` chip per certification the firm holds (both → two chips), only on a **confident** match.
- **Neutral factual attribute** — outline chip, `--ink2` text, no favorability color. It is NOT an endorsement and NOT a ranking input.
- **Absence of a chip ≠ "not certified."** It may just mean no confident directory match. The footer states this; never render a "not certified" negative.

### 7. Citywide track record (the enrichment — handle carefully)
- Pull from the same dataset behind the Chicago Discovery leaderboard, but **match on IL license number** (not name). Only render the citywide `.p2cite` stats when the match is **confident**; otherwise render the `.nomatch` fallback line.
- Citywide line is **factual activity only**: permit count (5 yr), optional total $ value, last-active year, dominant project type. **NEVER** import ranking language ("#1", "top", "best"), stars, or a quality score onto the property card. Volume ≠ quality.
- Do **not** surface "self-certified" as a positive on the card; it's mentioned once, neutrally, in the footer only.
- Apply to **both** current- and prior-owner firms (the prior-owner rehab team is the highest-value use of this context).
- `{PROFILE_URL}` → the firm's Chicago Discovery profile page.
- Stamp the citywide data with an "as of" date server-side; if the leaderboard dataset is stale beyond your refresh window, prefer the `.nomatch` fallback over showing outdated counts.
- Footer `.profind` is fixed copy (volume≠quality + match-by-license + verify) — always show it when any citywide line renders.

### 8. Violations: current vs. historical
- **Current window = last 5 years** from today. Count `open` violations in that window → drives the green hero `{OPEN_VIOLATION_COUNT} open violations` and header chip.
- Records **older than 5 years** go into the collapsible `.hist` block (default **collapsed**), header `{HISTORICAL_COUNT}` + one-line description.
- Violation item status:
  - `complied` (green) when resolved/complied.
  - `stale` (neutral grey, label "Open · {year}") when the record shows open BUT is >5 years old / no disposition recorded. **Never red.** A stale unresolved record from a prior era is not a current problem.
- The amber `.caveat` renders only when ≥1 historical record is `stale` (still shows "open"). If every historical record complied, drop the caveat.
- **A genuinely current, serious open violation (recent, unresolved) is the one case that may use red** (`--bad`) — that scenario isn't in this property's data but the component should support it: a recent open violation is a real problem and should read as one.

## CRITICAL DETAILS (check ALL)
1. **Owner-era split is DERIVED from last-sale-date vs. record dates** — computed in code, applied to both permits and violations. Two labeled dividers, era chip on every permit + professional row. Handle all three edge cases (empty current group / empty prior group / no sale date).
2. **Era chips are neutral/categorical** — indigo for current, grey for prior. NEVER green or red. Era is not good-or-bad.
3. **Permit status colors:** Complete = green; Expired/not-closed = **amber caution, not red**. Header mini-flag only when ≥1 open permit.
4. **List EVERY professional — no top-N/truncation.** Aggregated & deduped by firm (license-number key), **sorted most-recent-first**, tie-break design-professional-before-contractor. One row per firm, not one per permit. Role-agnostic: architect/engineer → indigo tag, any contractor/trade → grey tag, specific role in the label. Architect/GC names come from the **city/county permit API** (authoritative for on-property work).
5. **One match key (IL license #) governs BOTH citywide stats AND MBE/WBE.** If the permit API gives only a name, use normalized-name matching with a confidence threshold; below threshold, suppress BOTH enrichments (no stats, no cert chips) — never mis-attribute on a weak match.
6. **Citywide stats are activity, not a rating** — no "#1"/"top"/stars/scores on the property card; render only on confident match, else the `.nomatch` fallback. Self-cert stays out of the card body (footer only).
