## STEP 1 — Diagnose (15 min, do this first)

Paste before your API call, run one report, read the console:

```ts
const payload = JSON.stringify(evidence);
console.log("[DIAG] tokens ~", Math.round(payload.length / 4));
console.log("[DIAG] keys:", Object.keys(evidence));
console.log("[DIAG] saleHistory:", JSON.stringify(evidence.saleHistory ?? null));
console.log("[DIAG] taxes:", JSON.stringify(evidence.taxes ?? null));
console.log("[DIAG] projectType:", evidence.projectType ?? "MISSING");
```

- tokens under ~60,000 → not a context-window problem
- `saleHistory` price null → extraction bug, keep going
- also run: `grep -rn "\.slice(\|catch" --include=*.ts . | grep -v node_modules`

## STEP 2 — Stop false "not recorded" claims (biggest win)

1. Add `provenance.ts` to your project.
2. Wrap your extraction calls in `safeExtract()` so failures become
   `extraction_error` instead of `null`.
3. Add prompt patch **#6 FIELD STATUS RULE** from `PROMPT_PATCHES.md`.

Result: a field your parser drops becomes "could not be read — verify" instead of
"Last Sold: Not recorded." A gap instead of a falsehood.

## STEP 5 — Replace the memory context

Do **not** delete memory first.

1. Add `runStore.ts`.
2. Behind a flag (`USE_PROVENANCE=true`), build your `facts` record during extraction
   and call `saveRun()`. The `assertNoProse` guard will throw on anything
   conclusion-shaped — whatever it throws on is what your memory was carrying.
3. Add prompt patch **#7 PROVENANCE CONTRACT**.
4. Stop injecting memory into the payload when the flag is on.
5. Generate both properties with the flag on and off; diff.
6. Once clean: remove the memory read, then the memory write, then the module.

## STEP 6 — Keep it from regressing

1. Add `verify.ts`, call it after generation:

```ts
import { verifyReportNumbers } from "./verify";
verifyReportNumbers(generatedReportText, run);
```

2. Lock in golden values you already know are correct:

```
run 447: saleHistory[0].price = 411000
run 447: saleHistory[0].date  = 2014-04-14
run 447: taxes.2024.fullYear  = 16289.71
```

Assert these in a test so a future parser change fails loudly instead of shipping a
wrong report.
