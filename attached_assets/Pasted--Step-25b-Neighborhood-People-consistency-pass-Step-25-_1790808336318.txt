## 4. Daytime Economy — the broken tiles

**This is a real rendering bug, not a preference.**

`18200–18223` writes the tiles as `<span className="l">`, `<span className="n">`,
`<span className="s">`. `SBALoansView.tsx:121` writes the identical tiles as `<div>`. The CSS at
`.kyp-cxtile .l / .n / .s` never declares a `display`, so divs stack and **spans run inline** —
which is why the live section reads `JOBS HERE 577 workers commute in daily` on one wrapping line,
and why the `margin-bottom:7px` does nothing: vertical margins do not apply to inline boxes.

**Replace the whole `.kyp-cxtiles` block with `.kyp-blocks four` + `.kyp-block`:**

```jsx
<div className="kyp-blocks four">
  <div className="kyp-block ind">
    <div className="bv">{lodesData.workersInTract.toLocaleString()}</div>
    <div className="bl">Jobs here</div>
    <div className="bd">workers commute in daily</div>
  </div>
  <div className="kyp-block slate"> … Residents working … </div>
  <div className="kyp-block slate"> … Net daytime pull … </div>
  <div className="kyp-block slate"> … Higher-earning jobs … </div>
</div>
```

Markup order is **`.bv` first, then `.bl`, then `.bd`** — `.bl` carries `margin-top:8px`.

`.kyp-cxtiles` is the commercial-lending KPI strip from §19. It does not belong in §25. This one
change fixes the inline bug *and* the numeral size, because `.kyp-cxtile .n` is 24px while
`.kyp-block .bv` is 36px — which is why 25.3's numbers looked smaller than the rest of the section.

Keep the conditional: the fourth block still renders only when
`lodesData.highEarners > 0 && lodesData.workersInTract > 0`. **`.kyp-blocks four` with three
children is fine** — the grid is `repeat(4,1fr)` and the row is simply short.

### 5d. Places of Worship becomes a list, like Schools

**Delete the summary block at `18425–18430` entirely.** It renders `20` above the label
"Places of Worship within 1 mile" — while the subhead's own counter-text at `18391` already reads
`{totalCount} within 1 mile`. Same data, same question, twice on the same screen. The counter-text
stays; the block goes.

What remains is a list, and it should be built the way §21 Schools builds its lists — that is
already the report's pattern for "N things near here."

**Each religion group becomes a `.subwrap` with its own `KypSubhead`**, replacing the
`.kyp-charttitle` at `18433`:

```jsx
{sorted.map(([religion, places], i) => (
  <div className="subwrap" key={religion}>
    <KypSubhead className={i === 0 ? "first" : undefined}>
      <span className="lbl">{religion}</span>
      <span className="ct">{places.length}</span>
    </KypSubhead>
    <div>{places.map(worshipRow)}</div>
  </div>
))}
```

Pass no `subsection` — these are group headings inside 25.5, not numbered subsections, exactly as
`21.2 Elementary` / `21.3 High Schools` sit inside Schools.

**Two details that matter, both visible if you get them wrong:**

- **`first` on the first group only.** `.kyp-subhead` carries
  `border-top:1px solid var(--kyp-ink)`, so a group heading sitting directly under 25.5's own
  subhead draws a second rule with nothing between the two — an empty band. The existing
  `.kyp-subhead.first` modifier zeroes the border and the padding; that is what it is for. Later
  groups keep their rule, because there they separate two real lists.
- **The group count is the bare number**, not `{n} within 1 mile`. The radius is already stated in
  25.5's counter-text and again in the footer; a third time on every group heading is noise. With
  one group it also repeats the section's own total verbatim.

**Each row uses the school row primitive**, replacing the `.kyp-loanrow` at `18438–18446`:

```jsx
const worshipRow = (place) => (
  <div key={place.id} className="srow step23-list-row" data-testid={`row-worship-${place.id}`}>
    <a className="step23-name"
       href={`https://www.google.com/maps/search/?api=1&query=${encodeURIComponent(place.name + ' Chicago IL')}`}
       target="_blank" rel="noopener noreferrer">{place.name || 'Unnamed'}</a>
    <span className="step23-meta">{place.address}</span>
  </div>
);
```

`.srow`, `.step23-list-row`, `.step23-name` and `.step23-meta` already exist in `index.css` and are
already used by Schools. **No new CSS.** The row gains a maps link it does not have today, matching
`schoolRow` at `14122–14130`.

**Two things to know about this data before you build it.**

1. **`denomination` is always `null`.** `server/routes.ts:9348` hard-codes it. So the
   `{place.denomination && …}` branch at `18442` is dead code — it has never rendered. Drop it
   rather than carrying it forward.
2. **There is no distance field**, which is why the row has nothing in the right-hand
   `.step23-distance` slot that Schools fills with `0.14 mi`. **Do not invent one.**

   It is, however, cheap to add and it is the one thing that would make this list genuinely match
   Schools. The route at `server/routes.ts:9282` already receives `lat` / `lng` in the request body
   and already asks Google for `places.location` in its field mask (`:9297`), so the coordinates are
   in hand and thrown away. A haversine in the `acc.push` at `:9347` would return
   `distanceMiles` per place, the list could sort by it, and the row would take
   `<span className="step23-distance">{place.distanceMiles?.toFixed(2)} mi</span>`.

   **Treat that as optional and confirm with the owner before doing it** — it is a server change and
   this step is otherwise client-only. The target mock shows the list *without* distance, which is
   what today's data supports.

### 5c. A phrase in `.bv` takes `.txt`

`.bv` is for a numeral. Length, not point size, is what gives a block its weight — measured in
Instrument Serif at 36px, `577` renders **54px** wide, `D+72.7%` **139px**, and
`Strongly Democratic` **301px**. At a shared 36px the phrase has more than twice the ink of the
block beside it. At 24px it renders 201px and the two read as siblings.

Add `txt` to the two `.bv` elements whose value is a word or phrase:

- `18040` — `High` / `Moderate` / `Low` → `<div className="bv txt">`
- `18273` — `{electionData.classification}` → `<div className="bv txt">`

`.kyp-block .bv.txt` is in the patch. It is opt-in, so no other block in the report changes.
